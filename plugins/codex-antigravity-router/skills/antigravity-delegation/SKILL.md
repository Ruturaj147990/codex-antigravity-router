---
name: antigravity-delegation
description: Delegate coherent engineering outcomes to Antigravity through isolated Git worktrees when it reduces Codex effort without reducing quality; supports low and high risk work, FIFO scheduling, and a user-configurable worker limit.
---

Honor an explicit user instruction not to use Antigravity. Otherwise, identify delegation opportunities naturally while understanding the request; the user should not need to invoke this skill manually. Keep consequential architecture decisions and integration constraints in Codex. Delegate investigation, implementation, testing, and ordinary repair of a coherent outcome when Antigravity can do that work with less Codex supervision. A root-cause fix can be worthwhile even if its eventual patch is small. Complete obvious, very short work directly. Do not calculate a fixed prompt budget or split work into tiny tasks merely to use more workers.

Call `antigravity_status` once when needed. It reports the user's preferred model and `maxWorkers` ceiling. Submit one batch with `delegate_antigravity_tasks`; use the preferred model unless the task warrants another available model. Give each task a unique ID, LOW_RISK or HIGH_RISK flag, precise allowed paths, acceptance criteria, and only context that changes a decision or prevents a mistake. Reference repository files instead of pasting their contents. Preserve quality-critical constraints. Mark dependencies with earlier task IDs. Choose and pass `maxParallel` from 1 through `status.maxWorkers`: use fewer workers for dependent, overlapping, review-heavy, or small batches; use more only for independent outcomes with disjoint exact file scopes. Never exceed the user-configured ceiling. Use trusted-local verification only when the operator enabled it explicitly. Without that opt-in, run supplied checks only with a configured restricted execution provider. The controller runs ready tasks FIFO, isolates their edits in worktrees, checks CLI worktree identity, verifies allowed paths and supplied test commands, and guards integration against changes in the original checkout.

Resolve the authoritative Git repository from the current Codex task context and pass its absolute root as `workspaceRoot`. Do not infer it from Antigravity's last-opened IDE project or the plugin server's working directory. Reject ambiguous repository identity. Antigravity chooses relevant checks from authorized verification commands, but must not call terminal, command, notebook, or code-execution tools; the controller executes the selected checks in each assigned worktree through the explicitly configured execution provider and returns actual failures for repair. In trusted-local mode, controller commands run with the normal Windows user permissions; worktrees separate edits but are not a security boundary. Do not bypass the selected execution provider or run unrelated checks.

The preferred model, worker ceiling, and delegation enabled switch are user settings. `antigravity_dashboard` starts a local browser dashboard and returns a temporary loopback link. It edits the settings file at `%CODEX_HOME%\antigravity-router\settings.json` (normally `%USERPROFILE%\.codex\antigravity-router\settings.json`), which accepts `{"enabled":true,"model":"gemini-3.8-flash-low","maxWorkers":6}`. The dashboard binds only to `127.0.0.1`; its link carries a temporary token in the URL fragment, and API requests require that token. The page refreshes agent state every five seconds. Omitted settings fields use the MCP environment defaults. Valid worker ceilings are 1–32, matching the maximum batch size. `antigravity_status` verifies that the chosen model is available and reports the effective values. A task-level `model` or lower `maxParallel` may override the preference for that batch only; neither may exceed the configured ceiling. If Antigravity reports a quota/rate limit, the router preserves task work and history, disables future delegation, stops queued work, and cancels other active workers.

LOW_RISK work may integrate after independent verification. Read its concise result and verification status; do not routinely repeat Antigravity's investigation or review every diff. HIGH_RISK work stops at `awaiting_integration`. Decide whether direct code inspection is needed from the result and stakes; then call `antigravity_integrate` when satisfied. A conflict, escalation, denied permission, failed check, CLI identity mismatch, or interruption requires investigation. The worker tree and state file remain available. Use `antigravity_recover` to inspect or resume queued tasks; never rerun an uncertain task blindly.

The worker receives the task objective, risk, scoped paths, and acceptance criteria. It must investigate root cause, implement a complete solution, run appropriate checks, repair ordinary failures, and report concise evidence. It must stop and start its final reply with `ESCALATE_RISK:` when the task needs consequential architecture, security, or out-of-scope changes. No commits, pushes, resets, destructive cleanup, or further delegation.

Independent verification should use focused commands supplied by Codex when feasible. A passed command verifies its assertion, not all system behavior. Do not claim measured Codex credit savings without actual comparison data; prompt size and tool output are only proxies. Avoid sending large logs or transcripts to Codex.
