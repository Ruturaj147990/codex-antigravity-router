---
name: antigravity-delegation
description: Delegate coherent engineering outcomes to Antigravity through isolated Git worktrees when it reduces Codex effort without reducing quality; supports low and high risk work, FIFO scheduling, and a user-configurable worker limit.
---

Honor an explicit user instruction not to use Antigravity. Otherwise, identify delegation opportunities naturally while understanding the request; the user should not need to invoke this skill manually. Keep consequential architecture decisions and integration constraints in Codex. Delegate investigation, implementation, testing, and ordinary repair of a coherent outcome when Antigravity can do that work with less Codex supervision. A root-cause fix can be worthwhile even if its eventual patch is small. Complete obvious, very short work directly. Do not calculate a fixed prompt budget or split work into tiny tasks merely to use more workers.

Before starting any delegation batch, call `antigravity_dashboard` and open its returned temporary loopback URL in the available in-app browser so the user can review or change delegation settings. If no in-app browser is available, provide the URL to the user and wait for them to open it; do not say a local browser window was opened. Then call `antigravity_status` and use exactly its effective preferred model and `maxWorkers`. Never send a model override in a task batch; the configured preferred model is authoritative. Give each task a unique ID, LOW_RISK or HIGH_RISK flag, precise allowed paths, acceptance criteria, and only context that changes a decision or prevents a mistake. Reference repository files instead of pasting their contents. Preserve quality-critical constraints. Mark dependencies with earlier task IDs. Choose and pass `maxParallel` from 1 through `status.maxWorkers`: use fewer workers for dependent, overlapping, review-heavy, or small batches; use more only for independent outcomes with disjoint exact file scopes. Never exceed the user-configured ceiling. Use trusted-local verification only when the operator enabled it explicitly. Without that opt-in, run supplied checks only with a configured restricted execution provider. The controller runs ready tasks FIFO, isolates their edits in worktrees, checks CLI worktree identity, verifies allowed paths and supplied test commands, and guards integration against changes in the original checkout.

Resolve the authoritative Git repository from the current Codex task context and pass its absolute root as `workspaceRoot`. Do not infer it from Antigravity's last-opened IDE project or the plugin server's working directory. Reject ambiguous repository identity. Every supplied verification command is mandatory and runs in the listed order; Antigravity must not select or skip checks, and must not call terminal, command, notebook, or code-execution tools. The controller executes the checks in each assigned worktree through the explicitly configured execution provider and returns bounded stdout/stderr, exit status, timeout, and duration for repair. In trusted-local mode, controller commands run with the normal Windows user permissions; worktrees separate edits but are not a security boundary. Do not bypass the selected execution provider or run unrelated checks.

The preferred model, worker ceiling, and delegation enabled switch are user settings. `antigravity_dashboard` starts the local dashboard server and returns a temporary loopback link; it does not prove the browser displayed the page. It edits the settings file at `%CODEX_HOME%\antigravity-router\settings.json` (normally `%USERPROFILE%\.codex\antigravity-router\settings.json`), which accepts `{"enabled":true,"model":"gemini-3.8-flash-low","maxWorkers":6}`. The dashboard binds only to `127.0.0.1`; its link carries a temporary token in the URL fragment, and API requests require that token. The page refreshes agent state every five seconds. Omitted settings fields use the MCP environment defaults. Valid worker ceilings are 1–32, matching the maximum batch size. `antigravity_status` verifies that the chosen model is available and reports the effective values. The task payload cannot override the configured preferred model. If Antigravity reports a quota/rate limit, the router preserves task work and history, disables future delegation, stops queued work, and cancels other active workers.

Submission returns a durable handle immediately by default. Batches in the same repository run one at a time. Other repositories can use free worker slots up to the shared worker ceiling. Queue position describes the local repository queue. If the router restarts, use `antigravity_recover` on the saved batch to inspect or resume its queued work; uncertain active work is preserved for review. Within a batch, concurrent workers share one immutable source snapshot. A successful integration invalidates it so later tasks are based on the newly integrated source. The report exposes how many snapshots were prepared.

Submissions return a durable full `batchId` and revision `cursor` after a bounded wait. For longer batches, call `antigravity_wait` with the last cursor and advance it from each response and merge the changed tasks by ID. Use recovery without resume for a full report. Do not resubmit the batch. LOW_RISK work may integrate after independent verification. Read its concise result and verification status; do not routinely repeat Antigravity's investigation or review every diff. HIGH_RISK work stops at `awaiting_integration`. Decide whether direct code inspection is needed from the result and stakes; then call `antigravity_integrate` when satisfied. A conflict, escalation, denied permission, failed check, CLI identity mismatch, or interruption requires investigation. The worker tree and state file remain available. Use `antigravity_recover` to inspect or resume queued tasks; never rerun an uncertain task blindly.

The worker receives the task objective, risk, scoped paths, and acceptance criteria. It must investigate root cause, implement a complete solution, repair ordinary verification failures, and report concise evidence. It must stop and start its final reply with `ESCALATE_RISK:` when the task needs consequential architecture, security, or out-of-scope changes. No commits, pushes, resets, destructive cleanup, or further delegation.

Independent verification should use focused commands supplied by Codex when feasible. A passed command verifies its assertion, not all system behavior. Do not claim measured Codex credit savings without actual comparison data; prompt size and tool output are only proxies. Avoid sending large logs or transcripts to Codex.

For edit-only workloads, set `CODEX_ANTIGRAVITY_NO_EDIT_SECONDS` to a positive whole number smaller than the task timeout to stop for review if the worktree still has no edits at that point. Leave it unset for read-only work. The dashboard shows file tool activity and usage when the CLI reports them.

For untracked files needed as read-only context, supply repository-relative `contextPaths`. Untracked files outside `allowedPaths` and `contextPaths` are omitted from worker snapshots. Context paths do not grant permission to edit them.
